# Backup, import, and optional Cloud

## Coverage

| Format | Structured records | Managed media bytes | Recovery scope |
| --- | --- | --- | --- |
| Data-only JSON | Yes | No | Portable records; media references may be incomplete |
| Complete `.caizen` | Yes | Available full media required by backup preflight | Portable records and included files |
| Cloud Backup | One snapshot per account/profile | Separate private transfer with partial/retry states | Reviewed profile-scoped restore |
| Pre-import recovery | Previous structured workspace | No independent archive | Latest same-installation import rollback |

**Automatic Cloud Backup** is optional authenticated, account/profile-scoped upload. It is not live collaboration or conflict-free two-way record synchronization. Supabase Realtime events trigger metadata discovery, not automatic restore.

## Local formats and restore

`lib/storage/backup-schema.ts` defines data schema version `3`. Data-only export uses `format: caizen-data`, creation time, `{ profiles, currentProfileId }`, sanitized media metadata, and a media notice. It removes device paths, binary values, and device-only URLs. JSON import is bounded to 50 MiB and does not independently restore media blobs or the media metadata store.

Complete backups use an in-memory ZIP assembled with `fflate`:

```text
manifest.json
data.json
media/index.json
media/files/<asset-id>.<extension>
```

Current archive manifest version is `2`; supported version `1` archives remain readable. Creation checks referenced files and fails if required media cannot be included. Preview checks safe paths, required entries, versions, checksums when supplied, MIME/signatures, prototype-sensitive keys, and import integrity. Limits include 512 MiB archive size, 5,000 entries, and 25 MiB per uncompressed entry. Complete backups are not encrypted and may contain private records/files.

Restore previews counts, collisions, warnings, and missing media before selecting new-profile, merge, or replacement mode. It stores `preImportRecovery`, commits prepared structured state, reads it back to verify profile identities/counts, and attempts rollback on commit/verification failure. Merge uses record timestamps where available; new-profile import remaps collisions/references.

Complete restore stages media and compensates on structured failure. Restored archive files become local-only media with cleared remote paths. Thumbnails are not separate archive entries. IndexedDB and filesystem/media writes remain separate; partial failure must remain visible. The current backup-history store does not provide a full populated history UI.

Source owners include `lib/storage/import-integrity.ts`, `backup-repository.ts`, `media-storage.ts`, and `components/modals/BackupManagerModal.tsx`.

## Supabase setup

Cloud requires `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`. The client uses persisted PKCE sessions; local records remain available without configuration or sign-in. Never use a service-role key in client configuration.

## Cloud behavior and recovery

`lib/cloud-backup.ts` stores one structured `caizen_profile_backups` snapshot per authenticated account/profile, plus referenced media metadata/private files. Media transfer is separate from snapshot publication and can return incomplete results with retry guidance. Ordinary overwrite requires a known comparison baseline; intentional replacement carries reviewed backup/version/device guards. Newer unsupported backup schemas are rejected.

Background discovery fetches identity/timestamp/media summary metadata. Explicit Review downloads and validates the selected snapshot, reveals its records/files/warnings and replacement scope, and retains account/profile/backup/device revision guards through confirmation. A populated workspace replaces only a matching profile or adds a Cloud-only profile; unrelated profiles remain. Sign-in alone does not create/rename profiles, restore data, enable Automatic Backup, or end Demo.

Restore uses provider persistence pause, pre-import recovery, commit-boundary checks, read-back verification, and rollback handling. Cloud media normally downloads when opened; file failures remain visible with guarded retry. Profile/snapshot deletion and orphan cleanup retain account/ownership guards; Cloud deletion is separate from deleting local profiles.

Automatic Backup starts Off for each account/local-profile pair. A complete manual upload establishes eligibility; the user explicitly enables uploads. Local-newer upload uses an observed Cloud version guard. Ambiguous/conflicting states pause for review, never silently restore or force overwrite. There is no durable offline upload queue. Transfer admission and workspace/Demo locks serialize operations; media session fences protect account changes.

## Privacy and limits

- Exported records, media, and Cloud snapshots remain sensitive; complete backups have no encryption.
- The client anonymous key depends on correctly deployed owner-scoped RLS and private Storage policies.
- Local recovery covers the latest structured pre-import state on the installation, not device loss.
- Complete archives are memory-bound and large inputs can pressure browser/WebView memory.
- Cloud media and structured data have distinct transfer/rollback boundaries.
- Demo blocks real Cloud mutations and preserves its original-workspace recovery checkpoint.

Retained tests include backup validation, export/import round trips, import compatibility/integrity/transactional restore, media validation, and Supabase configuration contracts. Run them from the root with `pnpm test`. Tests, Cloud operations, and deployment checks were not run while preparing this public copy.
